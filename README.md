## Zephyr deployment builds

This repository contains two Zephyr deployment profiles:

- `rp2350Deployment` for Raspberry Pi Pico 2 (`RP2350`)
- `rp2040Deployment` for Raspberry Pi Pico (`RP2040`)

### Build targets

From the repository root:

```bash
make zephyr-rp2350
```

Builds the deployment for:

```bash
rpi_pico2/rp2350a/m33
```

From the repository root:

```bash
make zephyr-rp2040
```

Builds the smaller Pico-specific deployment for:

```bash
rpi_pico
```

The RP2040 path automatically selects:

- the dedicated `rp2040Deployment` topology via `-DFPRIME_DEPLOYMENT_PROFILE=rp2040`
- the Pico-specific Zephyr override file [rp2040.conf](/home/luca_lanzi/fprime-billee-rcm/rp2040.conf:1)
- smaller RP2040-only F´ configuration overrides from [config/rp2040-overrides](/home/luca_lanzi/fprime-billee-rcm/config/rp2040-overrides/CMakeLists.txt:1)

Those RP2040 overrides shrink the deployment so it fits the Pico's RAM by reducing:

- active-component stack sizes
- Zephyr's dynamic thread pool reservation
- communications buffer sizes and queue depths

### What is board-specific

The deployment logic itself is mostly board-agnostic because it uses Zephyr's chosen console UART inside the topology setup. In practice, the main board-specific pieces are:

- the `BOARD` value passed to Zephyr
- the selected deployment profile
- the Zephyr transport/device configuration
- the flash/debug runner selected by Zephyr for that board

### Running the GDS against the Pico

This deployment configures the F Prime communications driver to use Zephyr's chosen console UART at `115200` baud.

For the current RP2040 profile, the safest assumption is that this is a hardware UART, not USB CDC ACM. The Pico build now disables the unused Zephyr USB-device stack to save RAM. So for `rpi_pico`, connect a USB-to-UART adapter to the board UART that Zephyr exposes as the console.

On Linux that UART will typically appear as something like:

- `/dev/ttyUSB0`
- `/dev/ttyUSB1`
- sometimes `/dev/ttyACM0` if your adapter presents that way

Then launch the GDS from the repository root or from `rp2040Deployment` with UART transport enabled.

Because the flight software is running on the Pico, tell the GDS not to launch a local app and point it directly at the Zephyr dictionary:

```bash
./fprime-venv/bin/fprime-gds -n --dictionary build-artifacts/zephyr/fprime-zephyr-deployment/dict/rp2040DeploymentTopologyDictionary.json --communication-selection uart --framing-selection fprime --uart-device /dev/ttyACM0 --uart-baud 115200
```

If your port is present but the GDS is strict about validating it, you can add:

```bash
--uart-skip-port-check
```

So a more forgiving command is:

```bash
./fprime-venv/bin/fprime-gds -n --dictionary build-artifacts/zephyr/fprime-zephyr-deployment/dict/rp2040DeploymentTopologyDictionary.json --communication-selection uart --framing-selection fprime --uart-device /dev/ttyACM0 --uart-baud 115200 --uart-skip-port-check
```

If you prefer to keep the command shorter, you can run from [rp2040Deployment](/home/luca_lanzi/fprime-billee-rcm/rp2040Deployment/fprime-gds.yml:1) using the checked-in GDS config:

```bash
cd rp2040Deployment
../fprime-venv/bin/fprime-gds
```

That config already sets:

- `-n` / `--no-app`
- the Zephyr dictionary path
- `--communication-selection uart`
- `--framing-selection fprime`
- `--uart-baud 115200`

The device path is the piece you will most likely need to change between runs. The baud rate should stay `115200` unless you also change the `comDriver.configure(..., 115200)` call in [rp2040DeploymentTopology.cpp](/home/luca_lanzi/fprime-billee-rcm/rp2040Deployment/Top/rp2040DeploymentTopology.cpp:41) or the equivalent RP2350 topology file.

If you want the Pico to enumerate directly as a USB serial device instead, we can do that too, but it needs a separate board/devicetree setup so Zephyr exposes a CDC ACM UART as the chosen console.

### Current build prerequisite

The project root [CMakeLists.txt](/home/luca_lanzi/fprime-billee-rcm/CMakeLists.txt:6) requires `cmake 3.24.2` or newer.

If a build fails with an error like:

```text
CMake 3.24.2 or higher is required. You are running version 3.22.1
```

then the active shell or virtual environment is using an older CMake than this project allows, and that environment must be updated before the Zephyr deployment can be generated.
